# The DAW (src/daw/)

The DAW: its model (src/daw/model), files (io), library, the audio bridge (audio), views, widgets and the app.


The DAW's UI, built only from UI-layer components and the Theme, under the same rules: components pick surfaces and text roles, never colours or sizes. Controls that edit the project take a getter and a setter (or sync from the model each frame in `handleInput`) instead of holding a copy, so the arrangement, mixer, editors and dialogs always agree.

- **Devices in the DAW**: a track's `instrument` (an `audio::DeviceSetting`, `DeviceKind::None` for none; `hasInstrument()`) and `effects`, and `Project::masterEffects`, are its devices. `DevicePlace` (`Project.h`: master, track, index; `instrumentOf(track)`, `effect(master, track, index)`, `kInstrument`, `key()`) addresses any of them: `Project::device(place)`, `Project::effects(master, track)`. `DeviceCatalogue` (`DeviceCatalogue.h/.cpp`) is everything that can go in a chain, in one list rebuilt when the library or the plugins change (or one is turned off): `CatalogueEntry` (the device at its defaults, whether it is an instrument, its category, source ("Library", "Built-in", a vendor), description, path); `entries()`, `version()`, `find(key)`, `categories(instruments)`; library instruments by their library categories, the built-in VYBN Synth (category Synths, source Built-in), plugin instruments by features and name (`pluginCategory`: drums, else `guessCategory(name)`, else Synths or Keys for a sampler), effects by `effectCategories()` (Dynamics, EQ & filter, Delay & reverb, Distortion, Modulation, Utility, Other) from the built-ins' kinds and plugins' features. `DawApp::setInstrument(track, device)` is the one way a track gets an instrument (a non-instrument track or -1 gets a new instrument track named after it; the same device again keeps its values); `useDevice(key)` (the selected track), `dropInstrument(key, row)` (the browser's drag) and the picker go through it. `DevicePicker` (`DevicePicker.h/.cpp`), the one place devices are chosen: a popover beside what opened it, instruments or effects (`DevicePickerOptions`: title, the key in use, the anchor, `onPick`, Manage plugins..., Browser...), categories with counts on the left, the list (name, category and source, a Library/Built-in/Plugin or In use mark, an icon by kind) on the right, a search that has the keyboard as it opens; Up and Down move, Enter or a click chooses, Escape or a click outside closes; `DawApp::pickDevice(instrument, master, track, anchor)`. It opens from the instrument card's Change (or an empty track's Choose an instrument), the chain's Add effect, a track header's instrument line (`TransportHooks::chooseInstrument(track, line)`), a track's menu (Choose or Change instrument..., Add effect...) and Add track's Instrument track (a new track with no instrument asks for one). The Devices tab (`DevicesView`, below), a device's full view (`DeviceView`, below) and the browser (its instrument list is the catalogue's instruments) follow the same model.
- **Plugins in the DAW**: plugins are devices (`DeviceKind::Plugin`) wherever they are; one whose plugin isn't installed is kept (an effect passes the sound, an instrument is silent). `History` compares devices by kind, id, bypass and values (a new state alone isn't a step), names "Change instrument", "Remove instrument", "<device> settings", "Add effect (track)", and waits while a parameter is held in a plugin's own window. `AudioBridge`: `sync` applies each track's instrument and effects to its `TrackProcessor::chain` (and the master's), sets every chain's `setPlugins`, and `syncDevice(store, place, device)` brings a plugin's own changes and name back into the project; `chainOf(master, track)`, `deviceAt(project, place)` (the audio side's device for what the project has there now), `pluginSlots()` (every plugin in use); saving runs `captureStates` first (each plugin's state now into the project); exports render plugins offline (`PluginManager::setOffline`, `Slot::setOffline`), prepare the graph at the export's rate and wait while any slot is `busy()`. A library instrument is loaded by `AudioBridge::sync` for the track's `SamplerDevice` (asked again when the sampler is a new one) and handed to it. Settings > Plugins (`DawPlugins.cpp`, `buildPluginSettings`): the sandbox switch, Import plugin... (`importPlugin`: `.clap` files picked in the app's file dialog are copied into `Settings::pluginsPath()`, `%LOCALAPPDATA%\VYBN\Plugins`, and scanned), Scan again, Reload all, the folders (the standard ones, the imported plugins', the user's with a field to add one, and this run's `--plugin-folder`s), and each plugin found: kind, vendor, version, where it is in use (or its crash), On (off reloads its places, which then pass the sound or fall silent, and takes it out of the catalogue), Reload (`reloadPlugin(id)`: a fresh host, picking up a changed plugin), the folders it may read, or read and write in, with a field and Allow reading / Allow writing (`pluginGrant` lines, `id|folder` or `id|*folder` for writing), and files that couldn't be scanned with why. `applyPluginSettings` saves and hands the manager the new config. Project > Import plugin...; `openSettings("Plugins")` opens on that page. A device's full view: `openDevice(place, interface)` (a card's open button or its All parameters, a track menu's Open <instrument>; one per place, `deviceViews_`, keyed "T<track id>:<index>" (or "M:<index>") and holding its track by id (`OpenDevice::track`), so deleting an earlier track doesn't move it onto a neighbour; closed when its track is gone or its place no longer holds that device; asking again shows it) makes a closable `DockPanel` of the dock grid holding a `DeviceView` (`DeviceView.h/.cpp`), floated at first in a native window (800x560, or 1180x860 for a synth; on a plugin's interface it takes the interface's size) and dockable anywhere in the grid like the other panels. `DeviceView`: what it is and where (the name is on its tab or window), Bypass for an effect, Reload for a plugin that crashed or hung; for the built-in synth, Synth | All parameters (`SynthView`, below, opens first; the second page is the generic controls); Controls: every parameter drawn by the app (`addParamControl`, knobs of 52 px), grouped by module ("/A Filters/" shown as "A Filters"; groups with counts on the left, a heading per group under All) with a search, at most `kPageParams` (96) at a time; Interface (Controls | Interface, for a plugin that can be embedded; it opens on Interface when it has no parameters to show, else on Controls): its `PluginEditorView` (`PluginEditor.h/.cpp`), which finds the slot each frame, opens the embedded interface (again after a reload), copies each new picture into its `ImageData` and draws it pixel for pixel in an inset well, tells the host where it is on the desktop (and which window it is in) a few times a second, clips the frame to what it shows, and stands the frame aside under the app's overlays; `hideIfUnseen` (DawApp, each frame) moves the frame away when the view isn't shown (the Controls page, a hidden tab). The mouse and keys it sees (when the frame isn't over it) are replayed to the plugin. A plugin that can't be embedded has Its own window. Closing the view closes the plugin's interface. Latency: `AudioBridge::trackLatency(track)` (the chain's), `latencyText(track)` ("Plugin latency 2.7 ms, held 1.3 ms to line up") in the Devices tab's header, and each plugin card's footer gives its latency in samples. `pluginEditorDemo()` behind `--demo plugineditor`. `Settings` keeps `pluginSandbox`, `pluginFolder`, `pluginDisabled` and `pluginGrant` (`id|folder`) lines, and `pluginConfig()` builds the manager's config.
- **`Project`** (`Project.h/.cpp`): the model. `timing`, the song's `audio::TempoMap` (tempo points and time signatures; `AudioBridge` publishes it to the transport, and `beatsFor(start, seconds)` is how many beats a sound lasts from a beat), tracks (name, `TrackKind` audio or instrument, clips, `effects` (a list of `audio::DeviceSetting`), gain, pan, mute, solo, armed, `folded` (a group's: the tracks inside it are hidden in the arrangement and the mixer; saved, and like arming not an undo step), for instrument tracks the `instrument` device, and for audio tracks the `inputChannel`, `inputStereo` and `monitor`) with clips positioned in beats, the beats per bar, the timeline length in bars, `masterEffects`, and the shared selection (`selectedTrack`, `selectedClip`, `select`, `clip()`). Tracks and clips carry `id` (`ObjectId`, 0 = `kNoId`), unique in the project (clip ids across the whole project, separate from track ids), given by `normalizeIds(next)` (0 and every duplicate after the first get fresh ids; unique ids never change), with `trackIndex`/`findTrack` to find a track by id, and `trackShape` (ids and kinds in order, which views compare). Clips on instrument tracks hold `Note`s (start and length in beats from the clip's start, MIDI key, velocity, `muted`: kept but not played); notes past the clip's end don't play. They also hold `controls`: a `ControlLane` per controller used (`controller`, 0-127 or `kPitchBend`, and `ControlPoint`s, beat and value 0-1, sorted; `valueAt` joins them with lines, or holds for switches, `controllerStepped`, 64-69, and is the controller's `controllerDefault` with no points; `controllerName`). `splitClip` cuts the curves where it cuts (the right part starting with the value there) and `trimStart` keeps them in place. The loop: `loopStart`, `loopEnd` (beats; `hasLoop()` when the end is after the start) and `looping`, saved but not part of the undo history; `toggleLoop()` (Transport > Loop, Ctrl+L, the transport bar's Loop) turns it on over the selected clip (else the first four bars) when none is set. Clips on audio tracks name a sound file (`audioFile`) with `offset` (seconds into it), `gain` and `fadeIn`/`fadeOut` (seconds). `addTrack`, `deleteTrack`, `deleteClip`, `duplicateClip`, `splitClip(beat)` (notes go to the part they start in; the right part's offset moves on), `trimStart(clip, beat)` (keeps the content in place; not before the file's start), `secondsPerBeat()`. `exportPresets` (the export presets, a `std::vector<ExportPreset>`) and `exportMetadata` (`ExportMetadata`) are saved with the project; a demo or new project starts with `defaultExportPresets()`. `demoProject()` is the starting session: three guitar tracks (fingerpicked Am-F-C-G, a bassline, a tune) on the "Spanish classical guitar" library instrument (a `SamplerDevice` setting), a reverb on the tune, and three audio tracks. `newProject(instrument device, NewProjectOptions)` is what Project > New makes: the name, tempo, beats per bar and length chosen, with an instrument track (an empty four-bar clip) and an audio track if asked for. The demo's audio tracks have empty clips (drawn "Empty"). `demoProject()` and `newProject()` return projects with ids.
- **`ProjectStore`** (`ProjectStore.h/.cpp`): the project with every change to it passed through it. Readers get `const Project &`; a change goes through an edit call (`edit()` for anything, including tracks added or removed, `editTrack`, `editMix` for a track's name, gain, pan, mute, solo, armed, folded, monitor and input only, `editClip`, `editMasterEffects`, `editExportPresets`, `editExportMetadata` (the export presets and details: only `revision()` moves), `editSettings` (ONLY the name and length: only `revision()` moves, not the structure), `select`, `setTiming` (the tempo map, when it differs), `setLoop`, `toggleLoop`, `replace`, `restore(plan)`), which counts it as changed at once. `normalizeIds()` (`Project::normalizeIds` with the session's high-water mark, `nextId_`, so an id is never reused across `replace`, undo and redo) runs on construction (silently: the starting project is revision 1), on `replace`, at the start of `AudioBridge::sync`, at the start of DawApp's first FrameHook and before saving. It only looks when `edit()`, `editTrack()` or `replace()` ran since (`idsDirty_`), so an idle frame costs a flag test; when ids change it moves `revision()` and those tracks' `trackRevision` (not the structure). `restore(HistoryRestore)` applies an undo or redo through those same calls (a track's clips and devices through `editTrack`, its mix through `editMix`, the master's effects, the tempo map, the settings, the export presets and details, and the selection each only when the plan says they differ; arming, folding, monitoring and the loop are left alone), so undoing a one-note edit on one track moves that track's `trackRevision`, `revision()` and nothing else; a structural plan (tracks came, went, moved or changed kind) keeps arming, folding and monitoring by track id and the loop, and replaces the project. Revisions (`revision()`, `trackRevision(i)`, `mixRevision(i)`, `masterRevision()`, `selectionRevision()`, `structureRevision()`) only go up, so consumers compare numbers instead of the whole project. `ProjectSession` owns the store. Its `VYBN_VERIFY_STORE=1` verifier (run every 60 frames by DawApp's frame hook) prints `ProjectStore: ... changed without an edit` to stderr when the text or a track's content moved without its revision. Consumers compare revisions: `ProjectSession::recordHistory` and `checkModified`, and `AudioBridge::sync` (notes and clips), do no work while nothing they read has moved, so an idle frame doesn't scan the notes. Every write goes through the store: the views hold the `ProjectStore &` (never the project), and the readers get only `const` access (`ProjectSession::project()` and `DawApp::project()` are const), so a write has to name an edit call.
- **`Toml`** (`Toml.h/.cpp`, namespace `daw::toml`): a small TOML reader into a `Value` tree (`Table` keeps keys in order; `get(key, fallback)`, `at`, `arrayAt`), with errors as "line N: what". It reads comments, bare, quoted and dotted keys, `[tables]` and `[[arrays of tables]]`, one-line basic and literal strings, integers (hex, octal, binary, underscores), floats (exponents, inf, nan), booleans, multi-line arrays and inline tables. Multi-line strings and dates are refused. Writing helpers: `key`, `quote`, and `number`, which writes the shortest text that reads back as the same double or float.
- **`ExportModel`** (`ExportModel.h/.cpp`): what an export renders and how it is written, saved with the project as presets. `ExportTarget` (enabled, name, `ExportSource` Master/MasterDry/EachTrack/Tracks/Midi with its `tracks` by name, `ExportTap` post or pre fader, `respectMuteSolo`, `ExportRangeKind` Song/Timeline/Loop/Bars with `fromBar`/`toBar`, `tailSeconds`, `ExportFormat` Wav/Aiff/Flac/Mp3, bits, `bitrate` (MP3 only, kbps), sample rate, mono, `NormalizeMode` Off/Peak/Loudness with `peakDb` and `loudnessLufs`, the limiter and its ceiling, fades, `DitherMode`, `fileName` template, `folder`), `ExportPreset` (name, targets) and `ExportMetadata` (title, artist, album, comment). `defaultExportPresets()` gives "Mix", "Release" (Master WAV and Master FLAC, loudness-normalized), "Stems" and "MIDI". `enumName`/`fromName` give the lowercase names the file uses. `resolveFileName` expands the template tokens (`{project} {target} {track} {date} {time} {rate} {bits} {format} {preset}`), replaces characters Windows refuses with `_`, adds " - <track>" to EachTrack names without `{track}`, and adds the extension (`.mid` for Midi, `.mp3` for MP3; for an MP3 `{bits}` is its bitrate, "320kbps", and `{rate}` the rate it's written at). `mp3RateFor` gives the rate an MP3 is written at for a target's rate (32 kHz stays, 44.1 kHz and its multiples become 44.1 kHz, others 48 kHz): the dialog, the project file and `RenderJob` use it, and an MP3 is always dithered to 16 bits. `exportTargetRange` gives a target's part of the song in beats.
- **`ProjectFile`** (`ProjectFile.h/.cpp`): the `.vbp` format, version `kProjectFormat` (3; other versions are refused, so files from before devices no longer open). `writeProject` writes the root (format, name, the tempo map (`tempo` and `beats_per_bar`, the opening tempo and numerator, all an older build reads; `tempo_ramp` and `beat_unit` only when they say something; then `tempo_changes` and `signature_changes`, arrays of `{ beat, bpm, ramp }` and `{ bar, numerator, denominator }` from the second entry on, read back through `TempoMap`'s tidying), bars, and `instruments`, the library instruments used), a `[[tracks]]` table per track (name, kind `"audio"`/`"instrument"`, gain, pan, mute, solo, armed, `folded = true` on a folded group, and an audio track's input), then its devices (`writeDevice`): a `[tracks.instrument]` table and `[[tracks.effects]]` tables, each with kind (`"sampler"`, `"synth"`, `"effect"`, `"plugin"`), id, name, bypass, a plugin's state (base64) and `params`, an array of `{id, value}` tables; then `[[tracks.clips]]` tables (name, start, length, and on instrument tracks `notes`, an array of inline `{start, length, key, velocity}` tables, with `muted = true` on muted notes; and `controls`, an array of inline `{controller, points = [{beat, value}, ...]}` tables, values clamped, points sorted, one lane per controller, other controllers refused); the root has `loop_start`, `loop_end` and `looping` when a loop is set. `[[master_effects]]` tables hold the master's devices. `readProject` (`readDevice`) ignores unknown keys, refuses other formats, wrong types, unknown track and device kinds, unknown built-in effects, an effect as an instrument and a sampler or a synth as an effect, with a reason; a built-in effect's, a sampler's and a synth's values are clamped into range (unknown ones dropped, missing ones at their defaults; a synth's id must be `vibin.synth`); a missing name is the id; an audio track's instrument is ignored. The selection isn't saved. After the devices, `[export_metadata]` (only its non-empty fields) and `[[export_presets]]` tables (name, and `[[export_presets.targets]]` with every `ExportTarget` field, enums by name, `tracks` as an array of names) are written; `export_presets = []` in the root means no presets, and a file with no `export_presets` key gets `defaultExportPresets()`. Reading refuses unknown enum names with a reason, clamps numbers, and ignores unknown keys (the format number is unchanged). `saveProjectFile` writes `<path>.saving` and renames it over the target; `loadProjectFile` reads one. `instrumentsUsed` lists a project's library instruments once each (not synths). A device's table (`writeDevice`) also holds `sidechain = <track id>` when an effect is keyed (a non-integer or negative id is refused; `routingError`, which the reader runs after the master's effects are read, refuses an id no track has, a sidechain on a device that takes none or on an instrument, the track's own, a loop, and more than 4 keyed effects on a track or the master). Ids: `id = N` is the first key of each `[[tracks]]` and `[[tracks.clips]]` table when non-zero. It is optional when read (older files open and get ids); a non-integer, negative or larger than 4294967295 id is refused ("track N: id must be a whole number from 0 to 4294967295"; for a clip "track N: clip M: ..."), and `readProject` normalizes ids. The format number stays 3. `sameContent`, `sameSaved`, `describeChange` and the audio hashes ignore ids. If you add a field to the model, write and read it here and extend the self-test.
- **`Settings`** (`Settings.h/.cpp`): the user's preferences in `%APPDATA%\VYBN\settings.ini` (`key=value`): `library` (the sample library folder, default `Documents\VYBN Library`), `audioOutput` and `audioInput` by device name (empty for the default; the input `none` for none), `bufferFrames`, `freesoundKey` (the user's Freesound API key, set in Settings > Online), `audioThreads` (mixing workers besides the audio thread, -1 for automatic), `streamSamples`, `streamMemoryMB` (16-8192), `graphicsOverlays` (whether Vulkan's implicit layers, the overlays and capture tools other programs install, may load; off by default, from the next start), `nativeFileDialogs` (Windows' open and save dialogs instead of the app's; off by default), `autosave` (on by default), `autosaveMinutes` (1-30, default 2) and `autosaveVersions` (1-50, default 10) (see `Autosave`), `unusedSeconds` (how long unused instruments and sound files stay loaded; -1 until the app closes), one `midiDisabled` line per MIDI input turned off, and `pianoRoll` (the piano roll's view, `PianoRollView::writeView`) and `stepSequencer` (the step sequencer's view, `StepSequencerView::writeView`). `sampleCachePath()` is `%LOCALAPPDATA%\VYBN\Sample cache`. `main.cpp` reads them before adding the daemons, to configure the scheduler and the memory manager.
- **`Autosave`** (`Autosave.h/.cpp`): autosave and crash recovery for the project. While a project has unsaved changes (its store's revision moved, it is modified, the edit has settled), a copy of it is taken on the main thread every `autosaveMinutes` (from the first change, or the last autosave), and `writeProject`, the `.part` file and its rename, the manifest and rotation run on a Background job, one at a time (`AutosaveController`, which `update(session, settled, error)` runs each frame and reports `Autosaved`, `VersionSaved` or `Failed`; `saveVersion(session, label)` writes a manual version, never rotated). The folder is `autosaveRoot()` (`%LOCALAPPDATA%VybnAutosave`, or `VYBN_AUTOSAVE_ROOT`) with a folder per project (`autosaveKey` of its path) or per unsaved session (`untitledKey`), each holding `autosave-YYYYMMDD-HHMMSS.vbp` files and a `manifest.toml` (path, name, versions with time, kind and label; `writeManifest`/`parseManifest`, `rotate` keeps the newest `autosaveVersions` automatic ones). `session.lock` in the root names the running process (pid, start, key, path): `findRecoverable(root, now)` finds a session that ended without its lock being removed (its process isn't a running vybn.exe, and an automatic version is newer than the project's file or there is no file), for the startup recovery check. `VYBN_AUTOSAVE_SECONDS` overrides the interval (a test hook). A session whose recovery was declined keeps `declined.txt` in its folder (the newest autosave's time, `writeDeclined`/`readDeclined`, `recoveryDeclined`), so it is offered again only for a newer autosave. The autosave time as a list shows it is `autosaveTimeText` ("today 14:32", "yesterday 14:32", "18 Oct 09:05", "18 Oct 2025 09:05"); `readManifest` and `deleteVersion` (the file and its manifest entry) serve the Versions dialog. `ProjectSession::replace(project, path, saved)` takes the copy the file holds, so a recovered or restored project reads as modified against it. The UI is in `DawSaving.cpp`. `DawApp::offerRecovery()` (`main`'s `onShown`, posted so it runs after the first frames) shows "VYBN didn't close properly" over the found session (`recoverable_`, found in the constructor before the controller writes its own lock): "<name> has unsaved work from <time>.", with Recover (`recoverSession`: the autosave loaded as the project at its original path, which reads as modified against the file it came from, or against nothing for a project never saved), Show versions... (`showRecoverableVersions`), Not now (`declineRecovery`, which writes the marker) and Discard (`discardSession`: an unsaved session's folder is removed; a saved project's versions stay). Closing it counts as Not now. Project > Versions... (`project.versions`, no default key; `openVersions`, `openVersionsFor(folder, path, name)`) lists the folder's versions newest first (time, Auto or Manual, label, size) in a `ScrollView` of `ListItem`s, rebuilt after the frame when the manifest changes (polled every 30 frames): Open as copy (an unsaved copy named "<name> (version <time>)", after the unsaved-changes question), Restore (confirmed; `restoreVersion` first saves the current state as a manual "Before restore" version, then the project reads as modified against its file), Delete (confirmed; the list reopens without it) and Save version... (`openSaveVersion`, a name field, Enter saves). Project > Save version... (`project.saveVersion`, Ctrl+Alt+S) saves a manual version at once. Settings > Saving (`buildSavingSettings`): Autosave unsaved changes, Every N minutes (1-30), Keep N automatic versions (1-50) and Open autosave folder; `applyAutosaveSettings` saves them and reconfigures the controller (`autosaveInterval()`). `--demo versions` and `--demo recovery` are `versionsDemo()` and `prepareAutosaveDemo` in `main.cpp`.
- **`AudioPool`** (`AudioPool.h/.cpp`): the sound files clips play, loaded once each as Background jobs (long ones streamed through the environment's `MemoryManager`, if it streams) and shared, in a `ResourceCache` the `ResourceManager` sweeps (a file no clip player holds goes after the idle time and loads again when next asked for); `get(path)` (null while loading; a use), `add`, `loadNow(path, error)` (on the calling thread: File > Import audio file), `addRecording(path, rate, channels, samples)` (a take just written as a float WAV: a long one streams from it), `error`, `version()` (goes up as files arrive), `keepOnly`.
- **`RecordingSession`** (`Recording.h/.cpp`): recording onto armed tracks. `start(takeFolder)` plays the transport and makes a take: instrument tracks get a "Take N" clip from the bar it starts in, filled with notes as they are played (the sustain pedal lengthening them, moved earlier by the output buffer; other controllers and the pitch bend go into the clip's lanes as points, thinned when the take stops, and a take with only controllers is kept); audio tracks get a clip once the recorder starts (moved earlier by the round trip, through `offset` if before the timeline's start) that grows with a live overview (`preview`). `stop()` (or the transport stopping) cuts MIDI clips to whole bars (dropping empty ones) and, once the recorder lets go, writes each audio track's channel or pair as a 32-bit float WAV file in the take folder and gives the clip its file (`AudioPool::addRecording`: a long take then plays from that file, so it isn't kept in RAM). `update()` runs every frame and always drains the hub's stamped messages.
- **`AudioEditorView`** (`AudioEditor.h/.cpp`): the editor for the selected audio clip: its waveform (at its gain) on a ruler, the rest of its file dimmed beside it, drawn as Range plots (one per run of columns inside the clip or outside it) and its fades as Line plots. Drag the edges to trim, the top-corner handles for the fades; click to move the playhead, double-click to split; `zoom`, `fit`. Its waveform, fades and ruler are one draw cache (keyed by the store's revision, the clip's data, scroll, zoom and the hovered handle), so each frame draws only the playhead, except while the clip's sound is still loading, when everything paints.
- **`InstrumentLibrary`** (`Library.h/.cpp`): the library on disk: `<library>/Instruments/<Category>/<Instrument>/` and `<library>/Samples/<Category>/[<Pack>/...]`. `defaultCategories()` (Guitars, Bass, Keys, Drums, Percussion, Strings, Brass, Winds, Synths, Vocals, Loops, Effects, Other; any other folder is a category too) and `guessCategory(text)` (by keywords). An instrument folder directly in `Instruments` (the old flat layout) still counts, its category guessed from its name; names are unique (projects use them), the first found wins. `instruments()` (names), `entries()` (`LibraryInstrument`: name, category, folder), `samples()` (`LibrarySample`: name, category, pack, path, size), `find(name)`, `categories()`, `rescan()` and `version()` (up when a rescan finds a change). `import(files, error, category)` copies one .sfz with every sample and file it refers to (and .txt/.md files beside it, such as licences; the folder is named from its `//+ Name:` comment or file name) or note-named audio files (into a folder named after theirs), into a category (guessed when not given). `importSamples(files, category)` copies sound files. `installInstrument`/`installSamples` move a download into place (a taken name gets " 2"); `moveInstrument`/`moveSample` move between categories. `load(name, done)` loads as an Interactive job (with the environment's `MemoryManager`, so long samples stream) and calls `done` on the main thread through `Environment::post`; sets are cached by name and shared, in a `ResourceCache` the `ResourceManager` sweeps: a set no track's sampler or preview holds goes after the idle time (the preview sampler lets go of its set once the phrase has rung out). Its destructor joins the loaders. The guitar installed on this machine is FreePats' Spanish Classical Guitar (CC0), imported from the SFZ+WAV download.
- **`Json`** (`Json.h/.cpp`, namespace `daw::json`): a JSON reader into the TOML reader's `Value` tree (objects as tables in order, null as an empty table so lookups fall back), with `\uXXXX` escapes and surrogate pairs; errors as "at N: what".
- **`Archive`** (`Archive.h/.cpp`): `extractArchive(archive, folder, error, progress)`: zip files read here (stored and deflated entries through stb's inflate, Zip64, CRC-checked, paths that would leave the folder refused), other archives (.tar, .tar.gz, .tgz, .tar.bz2, .tar.xz, .7z) through Windows' own `tar.exe` (bsdtar), which reads the ones it was built for. `ExtractProgress` (bytes done and total, a cancel flag). `isArchive`, `crc32`.

- **`History`** (`History.h/.cpp`): undo and redo for the whole project, by snapshots. Nothing records itself: once a frame `DawApp` hands it the project, and when the content differs from the last state recorded (`sameContent`: tracks, clips, notes, mix, the tempo map (named "Change tempo" or "Change time signature"), project settings and export presets and details (named "Edit export preset" and "Edit export details"); not the selection, note selection, arming, folding, monitoring or ids) and the edit has settled (no mouse button held, no text field focused, not recording or exporting), the last state becomes a step named by `describeChange` ("Delete notes", "Move clip", "Mute notes", "Edit Mod wheel", "Track volume"; controller lanes are compared too, the loop isn't, and undo keeps the loop as it is now). So any new edit anywhere is undoable without knowing about it. `canMerge` joins a step to the last one when it is the same kind within half a second and no mouse was used (held keys, the wheel). A selection-only change updates the state, so undo puts the selection back as it was. `undo(store, now, plan)` first records a change still waiting; `redo(store, plan)` refuses once an edit has replaced what could be redone (judged by the store's revisions). At most `kMaxSteps` (200). Steps are `Snapshot`s in two levels: the project's own fields, and per track a shell (`shared_ptr<const Track>`: everything but the clips) and its clips (`shared_ptr<const Clip>`), each shared with the neighbouring step when identical (notes' selection included), so a step costs what it changed (`storedClips()`, `storedBytes()`). The last state recorded is kept in the same form, so a selection change or an edit waiting to settle copies nothing. `update(store, ...)` remembers the store's revisions as of that state and compares only the tracks whose `trackRevision` or `mixRevision` moved (every track, by index, when the structure moved), the project's fields only when `revision()` moved and the master's effects only when `masterRevision()` did; once a difference is seen on an unsettled frame it stops comparing until the settled one, and the step's label is worked out from the changed tracks alone. `update(project, ...)` is the same core with every track treated as moved (tests, and undo's own look). `undo` and `redo` return a `HistoryRestore` plan instead of a project: `structural` (the track count or the id and kind order differs) carries the whole project to replace with; otherwise it holds the fields that differ and the tracks whose parts differ (found by pointer, confirmed by comparing), each with whether its content and its mix changed. `ProjectStore::restore` applies it, then `adopt(store)` takes the store's revisions as the state's, so the next frame compares nothing. `matches(project)` says whether a project has the state's content; `current()` unpacks the state (not for per-frame use). `reset` when a project is opened or made. It is fed through `ProjectSession::recordHistory`, which runs `update` only while a store revision (or the selection's) moved since the last call, or a change is still waiting to settle; an idle frame costs two integer reads.

- **`RenderJob`** (`RenderJob.h/.cpp`): the offline render an export runs. `OfflineEngine` is a deviceless `AudioSystem` with its own `RealtimePool` (half the cores less one, normal priority, its threads marked offline; `pooled` false mixes on the render thread alone, which the self-test compares against), a `MidiHub`, a private `ProjectStore` holding a snapshot of the project (every track disarmed) and an `AudioBridge` over them, with the snapshot's master effects and the live master gain. `prepare(waiting)` runs once a frame on the main thread until it returns true: the graph is synced, every library instrument and sound file is in, and no plugin is settling; its chains and plugin slots are set offline (the global offline flags are not touched, so the live engine keeps playing). `beginRender(startBeat, tracks, preFader, unmuted)` taps the listed tracks (`TrackProcessor::setTap`) and settles for a quarter second, then plays from `startBeat`; `render` takes up to 4096 frames of the master, and `tapLeft`/`tapRight` give a track's tap for the last call. `RenderPass` renders one set of `PassOutput`s (the master, or the listed tracks summed, cut to a range and a tail that ends after a fifth of a second below -80 dB) into float temp files, measuring each with `LoudnessMeter` and `TruePeakMeter`, on the background thread that owns the engine. `cancel()` stops it within a block and deletes its files. A pass has one sample rate, one tap kind (pre- or post-fader) and one mute rule (outputs that ignore mute and solo need `unmuted`), so a job runs one pass per group: `setRate` (main thread only, between passes) prepares the graph at another rate, and `prepare` waits for plugins to settle, so the render thread never reads a plugin's state. `renderReady` is the readiness check the exporter waits on. The export self-test (`renderChecks`) checks the demo master rendered with the pool against one with no pool (within 1e-6), the stems against the dry mix, a cancelled render, and reports the speed. Finishing: `RenderJob` runs the whole export of a preset. It expands the targets into outputs (EachTrack: one per track with notes or audio; Tracks: the chosen tracks summed; MIDI: `writeMidiFile` from the snapshot), groups the audio outputs into passes by rate, tap and mute rule, and is driven once a frame on the main thread: `update()` makes the engine (or sets its rate), waits for `prepare()`, starts the pass on a Background job, and when it has ended starts one finishing job per output, which runs while the next pass renders. A finishing job reads the output's float temp file in 65536-frame chunks: gain (Peak: target minus the sample peak, or the true peak when the limiter is on; Loudness: target minus integrated, and with the limiter on the gain is corrected by the miss up to three times, keeping the best, before the file is written; Off: none), fades, the limiter (only when `limiter` is on and normalize isn't Off), mono, dither (16 and 24-bit), then the encoder with the project's metadata, and measures the final signal into a `TargetReport` (bytes, length, integrated LUFS, LRA, short-term maximum and series, true and sample peak, gain applied, clipped samples). `RenderJob::state()` is `Preparing`, `Rendering`, `Finalizing`, `Done`, `Failed` (some output failed; the reports say why) or `Cancelled`; `fraction()` weights the renders 80% and the finishing 20%; `status()` says what it is doing; `reports()` has one per output; `cancel()` returns at once and the job becomes `Cancelled` once its jobs have let go; its temp folder (`%TEMP%\VYBN export\<id>`) is removed when it ends. Destroying a job waits for its jobs, then frees the engine on the main thread. `ExportQueue` (`enqueue(snapshot, preset, masterGain, outputFolder)`, `jobs()`, `active()`, `update()`, `cancel(id)`, `remove(id)`) renders one job at a time, in order; an output without a folder of its own goes beside the saved project (passed in), else the library's `Exports` folder. `queueChecks` in the export self-test runs the queue through the environment's loop: the Release preset's loudness, true peak and FLAC against its WAV, Release and Stems together (timed), the MIDI preset, two sample rates in one preset, 16-bit WAV against FLAC, a loud mix at -9 LUFS under the limiter, a repeated name (numbered " (2)" and noted), and a job destroyed mid-render.

Settings (`openSettings`) is a dialog with a sidebar (a `ListView` of section items) beside a `Pages` of one `ScrollView` per section: Audio, Recording, Sample library, Performance, Online, Saving and Keyboard. Each section is its own block in `openSettings`, built with the `page(name)` helper. Settings has a Performance section (`buildPerformanceSettings`: mixing threads, streaming long samples, the stream memory, letting overlays hook in, using Windows' file dialogs, how long unused sounds stay loaded, the sample cache's folder, and live figures from the memory manager and each lane) and an Online section: the Freesound API key, a link to get one, and Edit sources (writes the defaults to `sources.toml` the first time and shows it). An instrument track's processor gets a `NotePlayer` with a `Sampler` (gain 0.5, since samples are near full scale and notes overlap) as its source. The arrangement, the mixer and the editor are `DockPanel`s in a `DockSpace` (`dock_`, which fills the body under the transport bar): by default the arrangement over the mixer, with the editor as the mixer's other tab. Each can be torn off into a floating window and docked anywhere in the grid; the arrangement's tools (Follow, zoom, Add track) and the editor's status are in their panels' headers. `showMixer`/`showEditor` show that panel's tab (or raise its window) and set its place's share of the split (double-clicking a clip opens the editor). The layout isn't saved. `importInstrument` runs the system open dialog from a posted action, imports the files and, if the selected instrument track has no instrument, gives it the new one. `studioTheme(dark)` is the DAW's theme: shallower shadows than the default (depth 3, softness 1.6), so the minimum gaps stay small in a dense layout. A zero-size `FrameHook` at the top of the body runs first each frame. It sets `ui.setBusy(...)` (the loop's fastest idle pace, see UISystem) while the transport plays, a take records or finishes, a count-in runs, an export job is active (`exporter_->queue().active()`), a download is active, the browser's preview plays, a plugin slot is busy (loading or reloading, `Slot::busy()`), or a sample set is loading (`InstrumentLibrary::anyLoading()`). An open plugin interface (a device view showing its interface) and an armed audio track (its input meter) set busy too, so their pictures and meters refresh at the full pace; with neither, the pictures refresh at the idle pace (up to 10 a second). It reads the output peaks once into `StereoLevels` (`AudioSystem::takePeak` has one reader; every meter shows the copy), runs `syncTracks`, which calls the bridge's `sync` (adds a processor for each new track, copies every track's gain, pan, mute and solo to its processor, reads each track's peak into the bridge's `levels()` for the channel strips, sends an instrument track's notes as a new `NoteSequence` whenever their hash changes, loads the track's instrument from the library when it changes and hands it to the sampler, and runs each player's `collect`). Every keyboard command is a keymap action: `defineActions` adds them before the menus are built, `loadKeybinds` applies the user's changes, and the menu items name them, so the menu bar runs them (Space plays because Transport > Play / pause is `transport.playPause`). `showShortcuts` (Help > Keyboard shortcuts, F1, and a button in Settings) opens the shortcuts editor, which saves through `saveKeybinds`. `addTrack` changes the tree, and the arrangement and the mixer rebuild themselves when they see it.
- **`Appearance`** (`Appearance.h/.cpp`): the DAW's look. `studioTheme(dark, preset)` is a preset's colours (Carbon, a deep neutral charcoal with a soft blue accent, by default) on the studio shape: depth 3, softness 1.8, corners 10, curvature 0.16, shadow strength 0.85, rim 0.55, control scale 0.9, text contrast 0.52 (shallow and fine-edged, so the dense layout's minimum gaps stay small). `appearancePresets()` (dark ones first). The user's look lives in `%APPDATA%\VYBN\theme.toml` (`preset`, `dark`, `base` and `accent` as "#RRGGBB", `depth`, `softness`, `corner_radius`, `shadow_strength`, `light_angle`, `curvature`, `edge_highlight`, `text_contrast`, `text_size`, `control_size`, `spacing`): `writeTheme`, `readTheme` (starts from the studio theme, so missing keys keep their defaults; bad colours are refused), `loadTheme`, `saveTheme`. `openAppearance(context, preset, onClose)` opens the Appearance window (DawApp keeps one: `showAppearance` toggles it, and its menu item and title-bar button show whether it is open), a non-modal `FloatingWindow` so the app changes as it is edited: preset swatches (each drawn in its own colours), Dark/Light, accent swatches and a hue, the background's tint, colourfulness and brightness, the surfaces (depth, softness, shadow strength, corners, curvature, edge highlight, light angle), text and layout (contrast, text size, control size, spacing), and Reset shape (the preset's colours on the studio shape). Its controls follow the theme each frame.
- **`TransportBar`** (`TransportBar.h/.cpp`): return to start, play/pause, stop (pressed again while stopped, it returns to the start), record (lit while recording; through `RecordHooks`), a `Readout` of bars.beats.ticks over the clock time, tempo (the BPM at the playhead; changing it changes the tempo point in force there, so with one point the song's tempo) with a Tap button (the tempo from up to eight taps, a two-second pause starting again), time signature (the one at the playhead, a button that opens its editor), the metronome and Loop toggles (under Playback), the inputs in use (the MIDI devices with an activity light, the audio input with a meter, and a line for recording messages), and the output meters. All on the real `audio::Transport`. `transportBeats` and `seekBeats` convert between the transport's samples and beats, and `setLoopBeats(start, end, on)` sets the transport's loop from beats.
- **`TimingLanes`** (`TimingLanes.h/.cpp`): the tempo map as two lanes under the arrangement's ruler, each with a header in the header column (the signature and BPM at the playhead, rising or falling in a ramp, and the tempo lane's scale). Hovering shows what a click would do: a ghost point with its bar and BPM in the tempo lane, a faint marker and "Double-click for a new time signature at bar N" in the signature lane; points and markers under the mouse show their place and tempo. Signature: a raised marker per change; double-click a bar to add one there (the signature in force; then its editor opens, `TimingHooks::editSignature`), double-click a marker to edit it, drag one along the bars, right-click for its menu (`signatureMenu`: the common signatures in one click, Other..., move the playhead there, delete); the first stays at bar 1. Tempo: the curve (held, or ramping), the area under it and its points on a scale of the points' range padded to tens (held while a point is dragged); click to add a point (snapped to the view's grid unless Shift; whole BPM, tenths with Shift), drag one between its neighbours (the first only in BPM), double-click one to type its tempo (`editTempo`), right-click for its menu (`tempoMenu`: ramp to the next, set, half or double the tempo, move the playhead there, delete). A click selects a point or marker (ringed) and Delete (the `edit.delete` action, before the clip's) removes it; a press elsewhere lets go. Right-clicking empty lane space opens the lane's menu (`laneMenu`: add a change there, a common signature from that bar, one tempo or signature for the whole song, hide the lanes). Empty lanes say how to use them. `DawApp::openTempoMenu`, `openTempoDialog`, `openSignatureMenu`, `openSignatureDialog` (numerator, unit and the common ones as buttons) and `openTimingLaneMenu` edit through `setTempoAt`, `setSignatureAt` and `ProjectStore::setTiming`. The arrangement's corner chip, left of the ruler, shows the tempo and signature at the playhead and shows or hides the lanes (as do View > Tempo and signature lanes and Ctrl+Shift+M; remembered in the settings as `timingLanes`); hidden, the ruler marks signature changes beside their bar numbers and tempo changes with dots. The lanes are drawn in the arrangement's cache (`key()`); the headers every frame.
- **`ArrangementView`** (`Arrangement.h/.cpp`): a ruler of bars (as long as their signatures make them) over the tempo and signature lanes (`TimingLanes`; View > Tempo and signature lanes, `showTiming`) and one lane per track in an inset well, with `TrackHeader`s (number, name, instrument or input, and its toggles (M, S, R, A and, when the app records automation, W) folded into one `RadialToggles` disc) on the left; double-click a track's name to rename it in place (`TrackName`: a text field over the name that changes it as you type and finishes on Enter, Escape or a click elsewhere, an empty name going back; `renameTrack(i)` starts it; the field takes exactly the room the name has, so it stays clear of the toggles). `trackAt(p)` (the track under a point, the track count for the empty space below, -1 outside) and `setDropTarget(row, hint)` (an accent outline across the row, with a hint in the empty space) serve drops from the browser and a scroll bar for time below. Press or drag on the ruler to move the playhead. Along the ruler's top, the loop strip (an inset groove; the project's loop a raised accent band in it, bright while looping, and faint across the lanes): drag to set the loop by bars (Shift by beats), drag its ends, click inside to loop or not, click outside to clear it. Press a clip to select it and drag it along its lane (snapped to beats) or onto another track. Drag a clip's ends to trim it (snapped to beats, Shift for free; audio not past its file). Double-click a clip to open it in the editor (`TransportHooks::openClip`), or an empty instrument lane to add a one-bar clip. Right-click a clip or a track for its menu (`clipMenu`, `trackMenu`). Instrument clips draw their notes (muted ones faint); audio clips their waveform (one Range plot a clip, a column per 2 px, each bar three quarters of it) and their fades (Line plots), and while recording the take so far (`audioFor`, `isRecording`). The wheel scrolls the tracks; Shift or a sideways wheel scrolls in time; Ctrl-wheel zooms in time around the mouse; middle-drag pans. `zoom(factor)` changes the scale, and it follows the playhead while playing (`setFollow`). It reaches the transport through `TransportHooks`, and arranges, routes input to and draws its headers itself, clipped to their column. It rebuilds the headers itself in `handleInput` when the store's `structureRevision()` moves and `trackShape` differs from what they were made for (not while a track name is being typed); `rebuild()` stays public. Its ruler, loop band, lanes, grid and clips are one draw cache (keyed by the store's revisions, the selection, the view, the hover and trim state, and the sound each shown audio clip plays; not reused while recording), and each frame draws the playhead, the track headers (their labels and toggles follow the input) and the drop target on top. Dragging a track's header reorders it (the others make room at the row it would land in): `dragBlock`, `settleDrop`, `dropOrder` and `moveBlock` in `Routing.h` keep folded groups whole. A folded group moves with the tracks hidden inside it, kept together in order right after it, and a drop that would fall between a folded group and its hidden tracks, or among them, goes to the nearer end, just before the group or just after its last hidden track. Folding is described under Routing in the app.
- **`SynthView`** (`SynthView.h/.cpp`): the VYBN Synth's own panel (a `DeviceView` page for a synth device), laid out like the front of a hardware synth in a scroll view: a preset bar (a dropdown labelled "Category / Name" over the factory presets then the user's "User / Name", showing the device's current name, which is shown on its own when no preset has it; Previous and Next, Save preset..., Init; choosing one is a single edit setting the values and the name), then four rows of raised cards, each a display of its part on top and its knobs below in tight rows (`addParamControl` through a `ParamCell`, which packs the name, the 40 px knob and its value a few pixels apart; the rows pack controls 6 px apart from the left): Osc 1 and Osc 2 (`WaveDisplay`, 52 px), Filter (a `FilterCurve`, 80 px: the magnitude response over 20 Hz-20 kHz from the TPT prototype, the cutoff's line and a raised handle on it; dragging sets the cutoff (log, across) and the resonance (up and down), a double-click resets both), Filter envelope and Amp envelope (an `EnvelopeDisplay`: the stages on a log-ish scale, three handles: the attack's peak (x = attack), the corner (x = decay, y = sustain) and the release's end (x = release), with a readout while dragging); LFO 1, LFO 2 (an `LfoDisplay` of two cycles, 56 px, dimmed when no slot uses it; Rate or Sync rate follows Sync, rebuilt in a posted action) and Sub & noise (a `SubDisplay`: the sub wave and the noise's tilt); Modulation (slots 1-3 and 4-6 in two columns, each line the slot, source, an arrow, target and a 32 px amount with its value beside it) beside Voice (Mode on its own line, the rest in a row). Each card's rows share the row's height; a row's widths are its cards' widths, so a row wider than the window scrolls sideways. Every display reads the current values each frame, so presets, undo and other editors show through. Each curve is a Fill plot (faint) under a Line plot (bright): the waves, the LFO cycles and the sub's wave (`drawCycle`), the filter's response (its Line 3 px thick) and the envelope's levels; the cutoff's guide and the noise's line are Lines. Each display is its own draw cache (`WaveDisplay`, `SubDisplay`, `FilterCurve`, `EnvelopeDisplay`, `LfoDisplay`), keyed by the values it reads and its drag state, so a settled panel draws from its caches. `SynthUserPresets.h/.cpp`: user presets are TOML files (`name`, `category = "User"`, a `[values]` table of `"<id>" = <value>`) in `%APPDATA%\VYBN\Synth presets` (`userSynthPresetFolder()`); `loadUserSynthPresets` clamps values to their ranges and drops unknown ids, `saveUserSynthPreset` refuses a name a file can't have (its folder is a parameter, so the self-test uses a temporary one).
- **`DevicesView`** (`DevicesPanel.h/.cpp`): the Devices dock panel (a tab beside the Mixer and Editor; View > Devices, Ctrl+3): a scrolling row of cards for the chain being edited: an instrument track's instrument first (or an inset card with Choose an instrument), then its effects, then Add effect (the picker). Every card is built the same way (`buildCard`) whatever the device: its name, its kind and source ("Plugin effect  /  VYBN", "Library instrument"), its gain reduction where it has a meter, Bypass (effects), an open button (its `DeviceView`), Change (the instrument) or move left/right (effects), remove; its first `kCardParams` (8) shown parameters as controls (`DeviceControls.h/.cpp`: `addParamControl` makes a switch for a toggle, a segmented control for up to four choices or a dropdown for more, else a knob with its name above and its value in the device's words below; `DeviceAccess` reaches the project's setting and the audio side's device, looked up each time; `paramValue` is the project's value, else a plugin's current one, else the default; `shownParams`, `deviceKindText`, `pluginStatus`); a library instrument's status line (loading, its memory, or why it is silent); a footer with All N parameters (and interface) and a plugin's sandbox, latency and late blocks; or, while a plugin loads or after a failure, crash or hang, a sentence and Reload. The panel's header has Track/Master (`setMaster`) and the target's name with its latency. The settings live in the `Project`, so undo, saving and sync follow. The cards are rebuilt after the frame when the target, its devices or a plugin's state or parameter list change (`signature`). `DevicesHooks`: `device(place)`, `openDevice`, `pick`, `latencyText`, `instrumentStatus(track)`. A card of a Compressor or Gate also has the Sidechain row and, while keyed, a "Keyed by <track>" line under its kind (the card's signature includes the key and the source's name); see Routing in the app.
- **`MixerView`** (`Mixer.h/.cpp`): `ChannelStrip`s (name, pan knob, `Fader` with a meter, gain and pan readout, M/S/R; pressing a strip selects its track) in a scroll view, an add-track button (a menu: Instrument track or Audio track, through the `onAddTrack` callback), and the `MasterStrip` fixed at the right, which drives the audio system's real master gain and shows the output meters. It rebuilds the strips itself when `structureRevision()` moves and `trackShape` differs: `handleInput` posts the rebuild, guarded by a shared `alive_` flag so a rebuild posted before the view is destroyed does nothing; `rebuild()` stays public. Each strip's meter shows its track's `TrackProcessor` peak (empty while the track is silent). Faders use a cubic taper (`faderGain`/`faderPosition` in `Format.h`): track faders go to +6 dB, the master to the AudioSystem's 1.5. Given the `AutomationWriter`, a strip's fader, pan knob and readout show the volume and pan playing at the playhead (`trackValueAt`), and moving them on an armed track while playing writes their lanes instead of the track's gain and pan; the master strip's fader and readout likewise show `masterVolumeAt` and write the master's volume lane while the master's writing is armed. It takes the app's `FoldState` (or keeps its own): a folded group's tracks have no strips (rebuilt when the fold version moves; `stripCount()`), and a group's strip has a `FoldChevron` beside its name.
- **`Actions`** (`Actions.h/.cpp`): `defineActions(keymap)`, the DAW's 60 actions (transport.loop is Ctrl+L, view.steps is Ctrl+5) (file.* and app.* are listed under Project, edit.undo and edit.redo under Editing) with their default keys (project.* including project.export, edit.undo, edit.redo, file.importInstrument, app.settings (Ctrl+,), app.quit, track.*, clip.duplicate, transport.*, view.*, help.shortcuts, notes.*), and the user's changed keys in `%APPDATA%\VYBN\keybinds.toml` (`[keys]` table of action id to a list of chords; only overrides are written; `loadKeybinds`, `saveKeybinds`, and `readKeybinds`/`writeKeybinds` for tests). Unreadable chords are skipped and reported.
- **`ShortcutsEditor`** (`ShortcutsEditor.h/.cpp`): `openShortcutsEditor(context, keymap, onChange)`, a dialog listing every action by category with its keys. Click a key to change it (the next key press is captured at `Priority::Capture`; Escape cancels), x removes it, + adds another, Reset goes back to the defaults (one action or all); a chord another action had is taken from it and the dialog says so. A search field filters. The list rebuilds after the frame whenever the keymap, the capture or the filter changes.
- **Track and clip menus** (`DawAudio.cpp`): what the old side panel did now lives where its things are shown. A track's menu (right-click its header): Rename (starts renaming in the header), Armed for recording, for instrument tracks Choose (or Change) instrument... (the device picker), Open <instrument> (its device view), Remove instrument and Add effect..., for audio tracks Input (None, each channel, each stereo pair of the open input, two until one is open), Hear the input while armed and Import audio file here..., and Delete track. A track's header shows the instrument's name (or "No instrument (click to choose)") under the name, or the audio input; clicking an instrument track's line opens the device picker beside it. A clip's menu: Open in the editor, Split here, Duplicate, Position and length... (`openClipDialog`: a dialog editing the selected clip's name, start bar, beat in the bar (keeping any fraction of a beat) and length in beats, live, clamped to the timeline), Remove fades on audio clips, and Delete clip. The Performance page keeps only the settings.
- **`Splash`** (`Splash.h/.cpp`): the loading screen, made first thing in `main` in the user's look (`loadTheme`): a card in the middle of the screen with the logo (a raised, domed disc with the accent waveform) in a groove, the name and "Loading", and an accent dot swooping round the groove (an ease-in-out cubic per 1.15 s lap, slow over the top and fast round the bottom) with a trail of 26 samples of where it was, so the trail stretches with its speed. A Windows layered window (per-pixel alpha, a soft shadow, no taskbar button) drawn with GDI+ (the bundled Inter for the text) on a thread of its own with its own message loop, paced by `DwmFlush`, so it needs no Vulkan device and keeps moving however busy the main thread is. `close()` starts a 0.16 s fade and returns; the destructor waits. It sets the process's DPI awareness (per monitor, version 2) before GLFW does. While it shows, `main` builds the app and the pool of spare tool windows (`UISystem::prepareSpares`), so the first seconds after the main window appears have no hitches. On this machine creating any window takes about 0.7 s (an injected overlay hooks window creation), so the splash appears a moment after launch; elsewhere it is near instant. Elsewhere than Windows it does nothing.
